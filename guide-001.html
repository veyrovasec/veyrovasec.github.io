How to Validate Python Function Inputs

Learn how to reject unexpected argument types, check acceptable values, and produce meaningful errors.

1. Why input validation matters

A function receives data from its caller. That data might not be the type or value the function expects. Input validation checks whether the data is acceptable before the function processes it.

2. Understand TypeError

TypeError is appropriate when a value has the wrong type for the operation or function contract.

For example, imagine a function expects an integer:

if not isinstance(threshold, int):
    raise TypeError("threshold must be an integer")

3. Remember that booleans are integers in Python

Python's bool type is a subclass of int. Therefore, isinstance(True, int) evaluates to True.

When a function should accept ordinary integers but not booleans, check for bool explicitly: 

if isinstance(threshold, bool) or not isinstance(threshold, int):
    raise TypeError("threshold must be an integer")

4. Understand ValueError

ValueError is useful when the type is correct but the value is outside the function's accepted range.

For example, a threshold might need to be greater than zero: 

if threshold <= 0:
    raise ValueError("threshold must be greater than zero")

5. Validate before processing

Put validation near the beginning of the function. This makes the function's requirements clear and prevents invalid data from reaching later operations.

6. Test both invalid and valid inputs

A useful test suite should check:

  • Unexpected data types.
  • Boolean values where ordinary integers are required.
  • Values outside the accepted range.
  • Valid boundary values, such as zero when allowed.
  • Whether existing expected behavior still works.

Final principle

Define what a function accepts, validate those requirements, and test the behavior. A function should not silently depend on assumptions about its arguments.
